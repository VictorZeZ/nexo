# nexo WebSocket Protocol

**Protocol version: 1**

The server is a signaling and relay backend. It stores and forwards end-to-end encrypted chat
ciphertext and relays WebRTC signaling. It never sees plaintext chat and never carries audio.

## 1. Transport

- Endpoint: `GET /ws` with a WebSocket upgrade. Use `wss://` in production.
- Encoding: UTF-8 JSON. The server sends text frames and accepts text or binary frames.
- Browsers: the `Origin` header must be in the server's `Cors:AllowedOrigins` list, otherwise the
  upgrade is refused with HTTP 403. A request with no `Origin` header is allowed.
- Upgrade failures: HTTP 400 (not a WebSocket request), 403 (origin not allowed), 429 (too many
  requests or too many concurrent connections from this IP).

Default limits (all configurable on the server):

| Limit | Default | Result when exceeded |
|---|---|---|
| Upgrade requests per IP | 100 per 60 s | HTTP 429 |
| Concurrent connections per IP | 20 | HTTP 429 |
| Maximum message size | 16 KiB | Socket closed with 1009 (message too big) |
| Inbound messages per connection | burst 60, sustained 30 per second | Socket closed with 1008 (policy violation) |

Treat any socket close as a reason to reconnect (see section 6).

## 2. Envelope

Every message, in both directions, uses this shape:

```json
{ "v": 1, "type": 10, "payload": { } }
```

- `v`: protocol version. Clients send `1`. Versions below the server's minimum are rejected.
- `type`: numeric message type from section 3. Enums are always sent as numbers, never strings.
- `payload`: always a JSON object. A missing or non-object payload is an `InvalidPayload` error.
- Property names are camelCase. Unknown extra fields are ignored.
- Timestamps are ISO 8601 UTC strings. Message IDs are GUID strings.

## 3. Message types

| Type | Value | Direction | Payload |
|---|---|---|---|
| JoinRoom | 1 | client to server | JoinRoom |
| LeaveRoom | 2 | client to server | LeaveRoom |
| RoomJoined | 3 | server to client | RoomJoined |
| CreateRoom | 4 | client to server | CreateRoom |
| ChatMessage | 10 | both | ChatMessage (client to server), ChatHistoryEntry (server to client) |
| MessageAck | 11 | server to client | MessageAck |
| RoomHistory | 12 | server to client | RoomHistory |
| ParticipantSpeakingStateChanged | 20 | both | SpeakingState |
| ParticipantLeft | 21 | server to client | ParticipantLeft |
| ParticipantJoined | 22 | server to client | ParticipantInfo |
| SetDisplayName | 30 | client to server | SetDisplayName |
| IdentityConfirmed | 31 | server to client | IdentityConfirmed |
| ResumeSession | 32 | client to server | ResumeSession |
| Heartbeat | 40 | server to client | Heartbeat |
| HeartbeatAck | 41 | client to server | HeartbeatAck |
| WebRtcOffer | 50 | both | WebRtcOffer |
| WebRtcAnswer | 51 | both | WebRtcAnswer |

Sending a type the server does not accept from clients (for example `RoomJoined`) is answered
with `UnknownMessageType`. Message type numbers are never renumbered or reused.

## 4. Payloads

### Client to server

**SetDisplayName**: `{ "displayName": string }`. Required, not blank, at most 32 characters.
The server trims it. Must be sent before `CreateRoom` or `JoinRoom`. Cosmetic only.

**CreateRoom**: `{ "roomName": string, "visibility": 0 | 1, "password": string? }`.
`roomName` at most 64 characters. Visibility `0` is public, `1` is private. A private room
requires a password of 1 to 128 characters. A public room must not include one. The creator joins
automatically and receives `RoomJoined` containing the generated join code in `roomId`.

**JoinRoom**: `{ "roomId": string, "password": string? }`. `roomId` is the 8-character join
code, at most 64 characters on the wire. Join codes use the characters `23456789` and `A-Z`
without `I`, `L`, `O`, and the server compares them exactly, so uppercase what a user types.
`password` is required only for private rooms, at most 128 characters.

**LeaveRoom**: `{ "roomId": string }`.

**ChatMessage**: 

```json
{
  "messageId": "guid",
  "roomId": "string",
  "ciphertext": "base64, at most 8000 characters",
  "nonce": "base64, at most 64 characters",
  "replyToMessageId": "guid?"
}
```

`messageId` is generated by the client and must not be empty. `ciphertext` and `nonce` are
AES-GCM output produced client-side. `roomId` must be the room this connection is in.

**ParticipantSpeakingStateChanged**: `{ "isSpeaking": boolean }`. Any `participantId` or
`displayName` sent is ignored.

**HeartbeatAck**: `{ "sentAtUtc": timestamp }`, echoing the `sentAtUtc` of the heartbeat.

**ResumeSession**: `{ "reconnectToken": string }`, at most 128 characters.

**WebRtcOffer** / **WebRtcAnswer**: `{ "toParticipantId": string, "sdp": string }`. `sdp` is at
most 10,000 characters.

**WebRtcIceCandidate**:
`{ "toParticipantId": string, "candidate": string, "sdpMid": string?, "sdpMLineIndex": number? }`.
`candidate` is at most 2,000 characters and `sdpMid` at most 32.

### Server to client

**IdentityConfirmed**: `{ "displayName": string }`.

**RoomJoined**:

```json
{
  "roomId": "string",
  "roomName": "string",
  "participantId": "string",
  "visibility": 0,
  "reconnectToken": "string",
  "participants": [ { "participantId": "string", "displayName": "string" } ]
}
```

Sent after create, join, or resume. `participantId` is this client's own identity in the room.
`participants` lists every other participant currently connected, excluding the recipient.
Each `RoomJoined` is followed by a `RoomHistory` message.

**ParticipantJoined** (payload `ParticipantInfo`): `{ "participantId": string, "displayName": string }`.
Sent to existing members when someone joins or resumes.

**ParticipantLeft**: `{ "participantId": string }`.

**RoomHistory**: `{ "messages": ChatHistoryEntry[] }`, oldest first, at most the last 200.

**ChatHistoryEntry** (also the payload of a relayed `ChatMessage`):

```json
{
  "messageId": "guid",
  "senderId": "string",
  "senderDisplayName": "string",
  "ciphertext": "string",
  "nonce": "string",
  "replyToMessageId": "guid?",
  "sentAtUtc": "timestamp"
}
```

**MessageAck**: `{ "messageId": guid }`.

**ParticipantSpeakingStateChanged** (relayed): `{ "participantId", "displayName", "isSpeaking" }`,
with identity always set by the server.

**Heartbeat**: `{ "sentAtUtc": timestamp }`.

**WebRtcOffer / WebRtcAnswer / WebRtcIceCandidate** (relayed): the sender's payload plus
`fromParticipantId`, always set by the server.

**ProtocolError**: `{ "code": number, "message": string }`. Messages are generic. Branch on `code`.

## 5. Error codes

| Code | Name | Meaning |
|---|---|---|
| 1 | UnknownMessageType | Type not recognized or not sendable by clients |
| 2 | UnsupportedProtocolVersion | Version below the server's minimum |
| 3 | MalformedEnvelope | Not a valid envelope |
| 4 | InvalidPayload | Payload missing, wrongly typed, or failed validation |
| 5 | InvalidRoomPassword | Wrong or missing password for a private room |
| 6 | RoomFull | Room is at capacity (default 50) |
| 7 | RoomTemporarilyUnavailable | Server-side storage problem, retry later |
| 8 | NotInRoom | The operation needs room membership |
| 9 | AlreadyInRoom | Leave the current room first |
| 10 | RoomNotFound | No such room |
| 11 | IdentityRequired | Send `SetDisplayName` first |
| 12 | SessionExpired | Reconnect token no longer valid |
| 13 | PeerNotFound | Signaling target is not connected to this room |
| 14 | RoomCreationLimitExceeded | Too many rooms created on this connection (default 10) |
| 15 | TooManyJoinAttempts | Too many wrong passwords for this room (default 10 per 10 minutes). Show "try again later" |

## 6. Flows

### Connect and join

1. Open the socket.
2. `SetDisplayName`, then wait for `IdentityConfirmed`.
3. `CreateRoom` or `JoinRoom`, then receive `RoomJoined` and `RoomHistory`.
4. Store `reconnectToken` from every `RoomJoined`, replacing the previous one.

A client already in a room that sends `JoinRoom` for that same room gets `RoomJoined` again with
no announcement to others. Joining a different room returns `AlreadyInRoom`.

### Heartbeat

The server sends `Heartbeat` every 20 seconds to every connection, including ones that have not
joined a room. Reply with `HeartbeatAck`. Any message from the client counts as activity, and a
connection silent for 45 seconds is closed.

### Chat

1. Generate a `messageId`, keep the message in a local outbox, and send `ChatMessage`.
2. The server stores it and replies `MessageAck`. Clear the outbox entry on ack.
3. Other participants receive the message as `ChatMessage` with a `ChatHistoryEntry` payload.
   The sender never receives an echo.
4. After a reconnect, resend anything still in the outbox with the same `messageId`. A duplicate is
   acknowledged again but is not stored or relayed twice.

### Reconnect

When the socket drops, open a new one and send `ResumeSession` with the latest token. No
`SetDisplayName` is needed. The response is `RoomJoined` with the same `participantId` and a
new token, or `SessionExpired`, in which case start over with `SetDisplayName` and `JoinRoom`.

- A token works once and is replaced on every `RoomJoined`.
- A participant's seat is held for 30 minutes after a drop, provided another participant is still
  connected. If nobody else is connected, the participant is removed immediately.
- A room with no participants is deleted immediately, including its history.
- Leaving a room with `LeaveRoom` invalidates the token.
- `ParticipantLeft` is sent when someone leaves explicitly or their seat expires. It is not sent
  at the moment of a drop.

### Voice (WebRTC mesh)

Audio is peer to peer. The server relays signaling only, and only between participants of the same
room that are currently connected. Signaling to yourself or to an absent participant returns
`PeerNotFound` or `InvalidPayload`.

1. On `RoomJoined`, the joiner creates a peer connection to each entry in `participants` and sends
   a `WebRtcOffer`.
2. Existing members create a peer on `ParticipantJoined` and wait for the offer, then reply with
   `WebRtcAnswer`.
3. Both sides exchange `WebRtcIceCandidate` messages as they are gathered.
4. On `ParticipantLeft`, close that participant's peer connection.
5. A `ParticipantJoined` for an already known `participantId` means that participant resumed.
   Replace the old peer connection.
6. The roster and `ParticipantJoined` can both name the same participant when two people join at the
   same moment, so treat a repeated ID as already known.

STUN and TURN server configuration is a client concern. The server does not supply ICE servers.

## 7. Encryption

Chat bodies are encrypted by clients with AES-GCM. The server only stores and forwards
`ciphertext` and `nonce`. The room key never reaches the server, and how clients obtain it is
outside this protocol.

## 8. Versioning

- The current version is 1. Additive changes, such as new optional fields or new message types,
  do not change the version. Breaking changes will.
- Message type and error code numbers are never renumbered or reused.
- The following were added during version 1 development, before any client existed:
  `participants` in `RoomJoined`, the `ParticipantJoined` message, error code 15, and the optional
  `participantId` on speaking state.
